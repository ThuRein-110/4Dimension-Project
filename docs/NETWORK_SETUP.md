# Local Network Setup

## Prerequisites

Windows 11, Node.js 22.12+, a modern Windows browser, iPhone Safari, and a trusted
Wi-Fi network. Guest Wi-Fi, AP/client isolation, VPN routing and school-network
firewalls can prevent peer-to-peer ICE connectivity. No TURN service is provided.

## First run

Run `npm install`, then `npm run dev` from the repository root. Open
http://localhost:5173 on Windows. Startup automatically generates a local CA and
a server certificate covering current IPv4 interfaces. These files remain local
in `.local/certs` and are never committed. The phone downloads only the public CA;
neither private key has an HTTP route.

Allow Node.js through Windows Firewall for the Private network profile. The
application does not modify firewall rules automatically. HTTPS uses TCP 5443;
public certificate download uses TCP 5442. WebRTC also uses dynamically allocated
UDP ports, so allowing the Node server alone may not suffice: the desktop browser
must be permitted on Private networks too. Do not create router port forwarding.

## iPhone certificate trust

1. In the desktop sidebar choose the PC address matching your Wi-Fi subnet.
2. Click First-time iPhone setup and scan the certificate-download QR. It opens
   `http://<pc-ip>:5442/livespace-ca.crt`. Allow the profile download in Safari.
3. Open Settings > General > VPN & Device Management (or Profile Downloaded).
   Install **4D LiveSpace Local Development CA**, entering the phone passcode
   if requested.
4. Open Settings > General > About > Certificate Trust Settings. Enable full
   trust for that CA. Only trust the certificate generated by your own PC.
5. Return to the PC and scan the main camera QR. It opens the HTTPS camera page.
6. Tap Start Camera, allow camera access, then Connect to PC.

Manually installed profiles need explicit SSL trust. See
[Apple's certificate-trust instructions](https://support.apple.com/en-us/102390).
Camera capture requires a secure context; see
[MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia).

Keep the phone unlocked with Safari in the foreground. Stop streaming with
the Stop button. Switch Camera intentionally changes to the front camera;
rear/environment is the initial preference. Browsers choose the exact available
camera and may reduce resolution or frame rate.

## Troubleshooting

| Symptom | Action |
| --- | --- |
| Certificate QR cannot open | Same Wi-Fi, correct subnet/address, private firewall allowance for TCP 5442 |
| HTTPS warns or camera API unavailable | Install CA and enable full trust; do not rely on bypassing a certificate warning |
| Page opens but video never connects | Permit browser on Private networks, disable client isolation/VPN; check same LAN |
| Permission denied | Enable Camera for this website in Safari settings; tap Start Camera again |
| Stream stops when phone locks | Unlock, return to Safari, restart camera if necessary |
| PC IP changed | Stop, `npm run certs`, restart, rescan updated camera QR |
| Pairing token expired or another phone occupies session | Click New pairing code, close old phone page, rescan |
| Port in use | Set PORT / HTTPS_PORT / CERT_PORT or stop the app already owning it |

## Removing trust

After the project, remove the LiveSpace certificate profile from Settings >
General > VPN & Device Management. Remove the local certificate directory only
when you intend to replace the CA. A renewed server certificate uses the existing
CA; creating a new CA requires trusting it on the phone again.
